# Callbacks

Tech.js supports **attribute-based callbacks** that allow you to execute JavaScript functions during different stages of the AJAX lifecycle.

Callbacks are useful when the behavior is specific to a single form, link, button, or trigger.

---

# Available Callback Attributes

| Attribute            | Description                       |
| -------------------- | --------------------------------- |
| `data-tech-begin`    | Called before the request is sent |
| `data-tech-success`  | Called when the request succeeds  |
| `data-tech-error`    | Called when the request fails     |
| `data-tech-complete` | Called after success or failure   |

Example:

```html
<form data-tech
      data-tech-begin="onBegin"
      data-tech-success="onSuccess"
      data-tech-error="onError"
      data-tech-complete="onComplete">
</form>
```

The value of each attribute must be the name of a global JavaScript function.

---

# Defining Callback Functions

```html
<script>
function onBegin(ctx) {
    console.log('Begin', ctx.options.url);
}

function onSuccess(ctx) {
    console.log('Success', ctx.response);
}

function onError(ctx) {
    console.error('Error', ctx.error);
}

function onComplete(ctx) {
    console.log('Complete');
}
</script>
```

---

# Callback Context Objects

Tech.js passes a structured context object to each callback.

## Begin

```javascript
{
  element,
  options
}
```

### Properties

* `element`: source DOM element
* `options`: request options generated by the handler

Example:

```javascript
function onBegin(ctx) {

    console.log(ctx.element);

    console.log(ctx.options.method);

    console.log(ctx.options.url);

}
```

---

## Success

```javascript
{
  element,
  response
}
```

### Properties

* `element`: source DOM element
* `response`: parsed Tech.js response object

Example:

```javascript
function onSuccess(ctx) {

    console.log(ctx.response.status);

    console.log(ctx.response.data);

}
```

---

## Error

```javascript
{
  element,
  error
}
```

### Properties

* `element`: source DOM element
* `error`: error object thrown by the request pipeline

Example:

```javascript
function onError(ctx) {

    alert('Request failed: ' + ctx.error.message);

}
```

---

## Complete

```javascript
{
  element
}
```

Example:

```javascript
function onComplete(ctx) {

    console.log('Always executed');

}
```

# Cancelling a Request

Returning `false` from `data-tech-begin` cancels the request.

```javascript
function onBegin(ctx) {

    if (!confirm('Continue?')) {

        return false;

    }

}
```

No network request is sent when `false` is returned.

# Working with Forms

```html
<form data-tech
      data-tech-method="POST"
      data-tech-url="/User/Save"
      data-tech-begin="disableSaveButton"
      data-tech-complete="enableSaveButton">

    <button type="submit" id="saveBtn">
        Save
    </button>

</form>
```

```javascript
function disableSaveButton() {

    document.getElementById('saveBtn').disabled = true;

}

function enableSaveButton() {

    document.getElementById('saveBtn').disabled = false;

}
```

# Reading Server Data

Controller:

```csharp
return Json(new
{
    success = true,
    message = "User saved successfully",
    userId = 15

```

Callback:

```javascript
function onSuccess(ctx) {

    console.log(ctx.response.data.userId);

}
```

# Custom Error Handling

```javascript
function onError(ctx) {

    const error = ctx.error;

    if (error.status === 401) {

        window.location.href = '/Account/Login';

        return;

    }

    alert('Unexpected error');

}
```

# Using Callbacks with Partial Updates

```html
<div id="result"></div>

<a data-tech
   data-tech-url="/Products/List"
   data-tech-target="#result"
   data-tech-success="afterProductsLoaded">
   Load Products
</a>
```

```javascript
function afterProductsLoaded(ctx) {

    console.log('Products loaded');

    // initialize additional widgets here

}
```

# Callback Execution Order

For a successful request:

```text
data-tech-begin
request sent
data-tech-success
data-tech-complete
```

For a failed request:

```text
data-tech-begin
request sent
data-tech-error
data-tech-complete
```

---

# Error Isolation

If a callback throws an exception, Tech.js catches it internally so the request pipeline is not broken.

```javascript
function onSuccess() {

    throw new Error('Test');

}
```

The error is logged to the console, but Tech.js continues running.

# Multiple Elements Using the Same Callback

```html
<form data-tech data-tech-success="notifySaved"></form>

<button data-tech
        data-tech-url="/Settings/Save"
        data-tech-method="POST"
        data-tech-success="notifySaved">
</button>
```

```javascript
function notifySaved(ctx) {

    console.log('Saved from', ctx.element);

}
```

# Relationship with DOM Events

Each callback has an equivalent DOM event:

| Callback             | Event           |
| -------------------- | --------------- |
| `data-tech-begin`    | `tech:before`   |
| `data-tech-success`  | `tech:success`  |
| `data-tech-error`    | `tech:error`    |
| `data-tech-complete` | `tech:complete` |

Use callbacks for element-specific behavior and DOM events for global behavior.

# Common Patterns

## Analytics

```javascript
function onSuccess(ctx) {

    console.log('Track success');

}
```

## Close Bootstrap Modal

```javascript
function onSuccess() {

    const modalEl = document.getElementById('editModal');

    const modal = bootstrap.Modal.getInstance(modalEl);

    modal.hide();

}
```

## Reset Form

```javascript
function onSuccess(ctx) {

    ctx.element.reset();

}
```

# Troubleshooting

## Callback Is Not Called

Checklist:

* Function is defined in global scope (`window`)
* Function name matches the attribute value exactly
* Script is loaded before the callback is needed

Correct:

```html
<form data-tech data-tech-success="onSaveSuccess"></form>

<script>
function onSaveSuccess() {}
</script>
```

Incorrect:

```html
<form data-tech data-tech-success="onSaveSuccess"></form>

<script>
const onSaveSuccess = () => {};
</script>
```

Arrow functions declared with `const` are not automatically added to `window`.

---

# Best Practices

* Keep callbacks small and focused.
* Prefer DOM events for cross-cutting concerns.
* Return `false` only from `data-tech-begin`.
* Avoid heavy DOM manipulation inside callbacks.
* Use `ctx.element` instead of querying the document when possible.
